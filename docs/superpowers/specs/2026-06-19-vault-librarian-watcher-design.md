# vault-librarian Watcher — Design Spec

**Date:** 2026-06-19
**Status:** Pending auditor approval (user delegated the approval gate to the auditor)
**Builds on:** the merged on-demand `vault-librarian` (PR #16)
**Repos touched:** `obsidian-plugin` (scan worker, `/ask` read-only change, `.state` relocation) + `claude-ceo` (playbook doc + registry entry)

## Problem

The shipped `vault-librarian` is a **waiter**: it does nothing until `/obsidian:ask` is invoked, and reconciles freshness lazily at query time. The user wants a **watcher** — a background process that continuously maintains the vault's knowledge layer and **proactively surfaces** what needs attention (unfiled notes, open `[ask]` questions, promotable clusters) without being asked. The on-demand `/obsidian:ask` path is kept (augment, not replace).

## Core invariant: exactly one *automated* writer

All Syncthing-conflict-proofing rests on this. The vault syncs across the MacBook and ML-1; two automated writers of the same `INDEX.md` / `Pending.md` guarantee `.sync-conflict` files (a prior incident). The invariant is **single automated writer**, enforced structurally:

- **Maintainer host = ML-1**, run via the CEO system. Because `ceo playbook scan` installs schedulers **only on ML-1** (`ceo-scan-only-on-ml1`), the watcher physically exists on exactly one host. A `maintainer_host` field in `obsidian.local.md` plus a hostname guard at the top of the worker (exit 0 if `hostname != maintainer_host`) is belt-and-suspenders so a stray invocation on any other host is a silent no-op.
- **Machine-owned files** (`INDEX.md`, `Librarian.md`, `Pending.md`): generated, with a header marking them machine-owned ("generated by vault-librarian — edits will be overwritten"). User prose goes in note *bodies*, never in these files. A human hand-editing `INDEX.md` is the one breach the invariant cannot prevent; the header is the mitigation.
- **Non-maintainer hosts never write shared knowledge-layer files.** `/obsidian:ask` QUERY is read-only; INSERT only creates the new note file (with `[ask]` markers inside the note body) — the watcher harvests it on the next scan.

## Architecture

### The watcher (CEO `runner:script` playbook on ML-1)

Scheduled by ceo-cron at a fixed cadence (default **every 15 min**, matching the CEO inbox cadence), with a **lockfile** so runs never overlap and a **debounce** so a Syncthing burst coalesces into one scan. Each run, on ML-1 only:

1. **Reconcile freshness** — for each domain folder, run the existing `vault_index_apply` to keep `INDEX.md` current. Walk **text files only** (exclude `.obsidian/`, `.trash/`, and attachment/binary dirs — the 579 MB is mostly attachments); the content-hash cache short-circuits unchanged notes.
2. **Surfacing checks** (v1 = three): 
   - **unfiled** — notes in `Inbox/` + coverage-gap notes present in no `INDEX`.
   - **open questions** — `[ask]` markers vault-wide + `Pending.md` entries, with age.
   - **promotable clusters** — folders with ≥ `moc_promotion_threshold` notes sharing a topic stem (reuse the `save-conversation` MOC stem-detection logic) — the proactive "want me to organize these?" signal.
   - *(Deferred to v2: dangling-link detection — requires parsing Obsidian link grammar `[[note#heading]]`, `[[note|alias]]`, `^block`, basename resolution; a naive check false-positives and trains the user to ignore the digest. Dup-candidate detection also v2.)*
3. **Digest** — overwrite `Librarian.md` at the vault root (machine-owned, ephemeral, current-state): frontmatter `status` / `last_scan` / per-check counts; body = sections per check with `[[links]]`.
4. **Transition-gated escalation** — compare each check's results to the prior-scan snapshot (in the local cache). Only **genuinely-new** items escalate:
   - Appended to `Pending.md` as `- [ ]` actionable lines (the user-facing queue).
   - High-priority new items also appended to `CEO/inbox.md` so the CEO agent is aware of vault-maintenance work.
   - No new items → only `last_scan` advances; nothing is appended anywhere. (The disk-monitor-spammed-the-inbox-64-times lesson, baked in.)

### State store (local, non-synced, on ML-1)

`.state` machine hashes **move out of the vault** to `~/.cache/vault-librarian/<vault-id>/` on ML-1, plus the prior-scan digest snapshot for transition detection. Nothing machine-only syncs, so there is no cross-host `.state` race and no Syncthing pollution. **First run on a cold cache snapshots silently** (records current state without flooding `Pending.md`/`CEO/inbox.md` — every note would otherwise look "new").

### `/obsidian:ask` changes (in `obsidian-plugin`)

- **QUERY** becomes a pure reader of the maintained `INDEX.md` — its on-demand `vault_index_apply` call is **deleted** (the watcher keeps the index fresh). If `now − last_scan > 2× interval`, QUERY prepends "⚠ index last maintained <T> ago (maintainer offline?)" so stale data is never served silently.
- **INSERT** creates only the new note file (with `[ask]` markers in the note body); it no longer writes `INDEX.md`/`Pending.md`.

### CEO registration (in `claude-ceo`)

- `CEO/registry.json` entry: `name: vault-librarian`, `runner: script`, `schedule` (cron, ~15 min), `script:` (the scan worker), `file:` (the playbook doc), `tier`, declared outputs.
- `docs/playbooks/vault-librarian.md`: name, description, schedule, **declared outputs** (`Librarian.md`, `Pending.md`, vault `INDEX.md` files, transition-gated `CEO/inbox.md`), origin, documented gaps.
- **Install:** `ceo playbook scan` runs **only on ML-1** (`ceo-scan-only-on-ml1`). The spec explicitly forbids scanning on the MacBook. The obsidian-plugin scan worker must be present on ML-1 (resolved via the CEO repo/plugin registry).

## Staleness story

ML-1 offline → `INDEX.md` goes stale; `/obsidian:ask` still reads it and warns; `Librarian.md` `last_scan` shows the age. Graceful and visible. No data loss — notes authored anywhere still sync; they're just unindexed until ML-1 is back.

## Out of scope (YAGNI)

Filesystem-event triggers (periodic poll is enough and tolerates Syncthing burstiness), dangling-link + dup-candidate checks (v2), embeddings, any write to shared knowledge-layer files from non-maintainer hosts.

## Testing

Bash test suites with a temp-vault fixture + a fake `$CEO_VAULT`. Tests must **fail when the relevant logic is reverted**:

- **Hostname guard:** worker exits 0 and writes nothing when `hostname != maintainer_host`.
- **Lockfile:** a second concurrent worker invocation exits without double-writing.
- **Reconcile:** existing `vault_index_apply` behavior preserved after `.state` relocation to the local cache (migrate the merged in-vault `.INDEX.state` tests to the new cache path).
- **Cold-cache first run:** snapshots silently — `Pending.md`/`CEO/inbox.md` get **no** new lines on the first scan of a populated vault.
- **Transition gating:** scan 1 surfaces N items; scan 2 with no vault change appends **nothing** new (only `last_scan` advances); scan 3 after adding one unfiled note appends exactly **one** `- [ ]` line.
- **Digest is machine-owned + overwrite:** `Librarian.md` is fully rewritten each scan; a hand-added line does not survive (documents the machine-owned contract).
- **`/ask` QUERY read-only:** reverting the deletion (re-adding the reconcile call) is caught; QUERY writes nothing to the vault. Staleness banner fires when `last_scan` is older than 2× interval.
- **INSERT note-only:** INSERT creates the note file but does not modify `INDEX.md`/`Pending.md`.
- **Attachment exclusion:** the walk skips `.obsidian/`, `.trash/`, and attachment dirs.

## Audit trail

Two auditor passes during brainstorming (`auditor-reviews-plans`):
1. **Framing audit** — reordered the clarifying questions (replace-vs-augment first, then freshness-vs-surfacing); forced single-host, local non-synced state, state-machine surfacing, and debounce into the design rather than asking them.
2. **Design audit** — HIGH: "single writer" is false once a human edits `INDEX.md` → restated as single *automated* writer + machine-owned headers; HIGH: the merged on-demand `.state` writer must be *deleted in the diff*, not just superseded; HIGH: `.state` relocation orphans merged tests + cold-cache floods Pending → migrate tests + silent first-run. MED: hard-pin maintainer via config + hostname guard (not "recommend"); `Librarian.md` machine-owned; dangling-links cut from v1. LOW: ship 2–3 checks, defer dup; exclude attachment dirs; `/ask` active staleness banner.

(A third auditor pass on this written spec is the gate the user delegated; the watcher's `maintainer_host = ML-1, run via CEO` decision is incorporated above.)

## Plan-time follow-ups (from the approval audit — APPROVED)

The approval auditor cleared the spec with three items to resolve in the implementation plan (none are design flaws — transition-gating already forecloses the catastrophic spam mode; these are precision refinements):

1. **Define the concrete `CEO/inbox.md` escalation predicate.** "High-priority" must become an explicit rule — e.g. *only `open-questions` items aged > N scans escalate to `CEO/inbox.md`; `unfiled` and `promotable-cluster` items stay in `Librarian.md`/`Pending.md` only.* Add a test asserting a routine new unfiled note appends to `Pending.md` but **not** `CEO/inbox.md`.
2. **Atomic digest write.** `Librarian.md` overwrite must be write-temp-then-rename so a mid-Syncthing-sync read never sees a half-written digest.
3. **Pin worker resolution on ML-1.** Specify exactly how the obsidian-plugin scan worker is located on ML-1 (CEO repo/plugin registry path), not just "resolved via the registry."
